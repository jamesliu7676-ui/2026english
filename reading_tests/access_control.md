# 網頁身份管制方案

## 目前狀態

`quiz.html` 已加入前端身份驗證入口，使用者需輸入：

- 使用者代碼
- 進入碼

通過後才會載入題庫頁面。

目前身份差異：

- 教師：可展開答案與解析。
- 學生：只顯示題目，不顯示答案與解析。

目前示範進入碼：

| 身份 | 進入碼 | 用途 |
|---|---|---|
| 教師 | `ENG-TEACHER-2026` | 管理與預覽 |
| 學生 | `ENG-STUDENT-2026` | 一般練習 |

使用者代碼請使用匿名代碼，例如：

- `class-a-01`
- `class-a-02`
- `teacher-01`

不得使用學生真實姓名。

## 重要限制

目前專案是靜態網頁，若部署在 GitHub Pages，網頁與 JSON 題庫檔案仍然是公開檔案。

前端身份入口只能做到：

- 擋住一般直接進入頁面的使用者
- 建立班級入口感
- 記錄使用者代碼於瀏覽器 session
- 區分教師與學生入口
- 讓教師與學生看到不同頁面功能

前端身份入口不能做到：

- 真正保護題庫檔案不被下載
- 防止懂技術的人查看原始碼
- 防止直接開啟 `question_bank.json`
- 作為正式帳號密碼系統

## 真正身份管制方案

若題庫內容需要真正限制訪問，建議改用下列方案之一：

| 方案 | 適合情境 | 說明 |
|---|---|---|
| Cloudflare Access | 網頁仍要公開網址，但只允許指定 email 登入 | 最適合快速加上 Google / email 驗證 |
| Firebase Authentication | 需要學生帳號、登入紀錄、日後成績追蹤 | 適合做成正式學習系統 |
| Supabase Auth | 需要帳號、資料庫、練習紀錄 | 適合題庫與作答紀錄都要管 |
| 私有 GitHub Pages 替代部署 | 只給少數人看 | 改用可設定登入的主機或平台 |

## 建議路線

第一階段：

- 保留目前 `quiz.html` 的前端身份入口。
- 使用匿名使用者代碼。
- 不放正式個資。
- 不把進入碼當作真正安全保護。

第二階段：

- 若要正式管制進入人員，優先採用 Cloudflare Access。
- 設定允許名單，例如教師 email、學生 Google 帳號或指定網域。
- 將 GitHub Pages 網址放到 Cloudflare 後面，由 Cloudflare 擋登入。

第三階段：

- 若要記錄學生作答、分數、錯題，改接 Firebase Auth 或 Supabase Auth。
- 題庫與作答紀錄改由後端或資料庫提供，不再把完整題庫直接公開成 JSON。

## 後續可新增功能

- 教師身份顯示答案，學生身份預設隱藏答案。
- 依使用者代碼記錄最近出題紀錄。
- 依班級代碼分派不同題組。
- 匯出作答結果。
- 管理允許名單與停用名單。
